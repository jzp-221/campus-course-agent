# P5：删除关联检查与课程清空

本阶段采用 **有关联则禁止删除，提示先清理** 的策略。不级联删除，不自动改成禁用；外键约束保留，关联课表、学习计划和文档仍可追溯。管理员不能删除自己。

接口沿用 `{code,message,data}` 业务包络：业务错误通常是 **HTTP 200 + code=400/403/404/409/503**，鉴权缺失仍 HTTP 401，参数结构错误仍 HTTP 422。前端现有 request 拦截器按业务 code 显示错误，不会把 HTTP 200 等同操作成功。

## 触发方式与预期结果

| 触发方式 | 业务码 / 消息 | 保留或变更的数据 |
| --- | --- | --- |
| 删除没有课表引用的课程：`DELETE /api/course/{id}` | 200，请求成功 | 删除该课程 |
| 删除已有 N 条课表的课程 | **409**，“该课程已有 N 条课表安排，请先删除或调整这些课表” | 课程与所有课表保留 |
| 删除/更新不存在的课程 | **404**，“课程不存在” | 不产生变更 |
| 删除有关联的学生：`DELETE /api/user/{id}` | **409**，“该用户仍有关联数据：课表 N 条、学习计划 M 条、上传文档 K 份，请先清理后再删除” | 用户与全部关联数据保留；仅列出实际阻塞的类型 |
| 删除没有关联的其他用户 | 200，请求成功 | 删除该用户 |
| 删除当前登录管理员自己 | **403**，“不能删除当前登录的账号” | 当前账号保留 |
| 删除/更新不存在的用户 | **404**，“用户不存在” | 不产生变更 |
| `PUT /api/course/{id}`，`{"description":""}` | **200** | 简介清空为 `""`，后续列表回查仍为空串 |
| 同接口仅传 `{"name":"新名称"}` | **200** | 简介、编码及其他未提供字段保持原值 |
| 同接口传 `{"code":""}` 或纯空格 | **400**，“课程编码不能为空” | 编码及同请求的其他字段都不变 |
| 新增/更新课程名称为空白 | **400**，“课程名称不能为空” | 不保存无效名称 |
| 新增/更新课程编码与另一课程重复 | **409**，“课程编码已存在” | 原记录保留 |
| 删除/更新不存在的课表 | **404**，“课表不存在” | 不产生变更 |
| 删除不存在或不属于本人的学习计划 | **404**，“学习计划不存在” | 不删除他人数据 |
| 给非学生安排课表 | **400**，“只能给学生安排课表” | 不保存 |
| 排课所引用的用户/课程不存在 | **404**，“用户不存在” / “课程不存在” | 不保存 |
| 删除/重建不存在的文档 | **404**，“文档不存在” | 不产生变更 |
| 检查完成后发生外键或唯一性竞争 | **409**，“数据存在关联或唯一字段冲突，请先清理关联或核对数据” | 回滚失败事务，不返回成功 |
| 数据长度/格式违反数据库要求 | **400**，“提交的数据格式或长度不符合要求” | 回滚失败事务 |
| 数据库连接、查询、提交或结果确认失败 | **503**，“数据库暂时不可用，操作结果未确认，请稍后回查” | 不宣称保存/删除成功；提交回包丢失时结果可能已生效，先回查 |

文档发生数据库失败时消息另带失败文件名与处理阶段，业务码仍按上述 SQL 分类。原有抽取/embedding/Chroma 失败码与补偿行为保留。

## 后端修改

`course_service.delete_course` 先锁定父课程行，再检查引用课表；`user_service.delete_user` 同样锁定目标用户，逐类检查课表、计划、上传文档。关联读取使用当前锁定读，避免 MySQL REPEATABLE READ 的鉴权旧快照漏掉刚提交的数据；锁持有至提交或回滚。仍以数据库外键处理最后的并发竞争，不放宽约束。

`app/common/db_errors.py` 在课程、用户、课表、学习计划和文档写入服务边界统一转换 SQLAlchemy 错误：IntegrityError → 409，DataError → 400，其他 SQLAlchemyError → 503。失败回滚，业务异常原样传播并释放事务锁。日志只记录操作与异常类型，**不返回或打印异常的 SQL/参数/连接串**。

`get_db` 同时处理写入服务执行前的鉴权数据库错误及会话关闭错误。全局未知异常兜底继续返回 HTTP 500 的“服务器内部错误”，用于未预期故障；普通关联阻塞、资源不存在、校验错误和数据库故障有明确业务出口。

文档原有文件/向量补偿保留。即使 rollback 自身失败，也继续尝试文件、向量清理，并明确“数据库回滚未确认”；COMMIT 丢失回包不宣称“整批已回滚”。删除文档可能已提交而回包丢失时返回 503、“删除结果未确认，请回查文档列表”，不会改成无关的 404 或假返回成功。故障恢复后核对记录、文件及向量，再执行清理或重新上传。

课程更新使用 `model_dump(exclude_none=True, exclude_unset=True)`：未提供字段不修改，空串不是 None，因此简介 `""` 会进入更新。沿用既有 null=不修改的行为。**课程编码继续必填且唯一**，空串/空白明确 400；不靠忽略空字段规避校验。

## 前端修改

`Course.vue` 保存实际调用 `buildCoursePayload`，移除 `description || null` 与 `code || null` 的转值。helper 只携带已提供且非 undefined 的业务字段，空串原样进入请求；未提供字段省略。编辑回填使用 `??`。

课程名称原有 required 校验保留；编码 required 校验保留并拒绝纯空白，提示改为“必填，唯一”。空编码会先在页面明确校验，直接调用 API 时也有后端 400；简介可清空。新增测试编译真实 Vue setup 并执行保存方法捕获 API JSON，覆盖空串实际提交和无效表单不提交。
