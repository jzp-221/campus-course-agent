# P8 周课表：第一阶段报告

本阶段完成数据模型、独立迁移、周次与日历工具、可重复运行的演示种子脚本。暂停在此阶段，等待确认后再实现周课表接口和前端周视图。现有列表接口与 `Schedule.vue` / `ScheduleManage.vue` 保留。

## 固定规则与配置

- 节次维持 `1-2节 / 3-4节 / 5-6节 / 7-8节` 四档。
- 第 1 周周一是 `2026-09-07`，共 20 周，最后一天为 `2027-01-24`。
- 每门课固定一个实际星期与节次，所有周次保持同一个格子；一个学生的同一天、同节次最多一门课。
- `start_week <= 当日周次 <= end_week` 才展开该课程，同时必须满足 `is_class_day`。
- 种子采用固定随机种子 `20261010`，周次范围包括 1–20、1–16、3–8、9–16 和 1–8；教师和教室也固定且可复现。

`app/config.py` 新增默认值，`.env.example` 提供配置说明：

```ini
SEMESTER_START_DATE=2026-09-07
TOTAL_WEEKS=20
```

本次没有修改 `.env`，实际使用上述代码默认值。没有修改 P5 删除规则、RAG 阈值或四份课程资料。

## 新增字段与迁移

`app/models/schedule.py` 新增三列，ORM 默认值与数据库默认值同步：

| 字段 | 类型 | 可空 | Python 默认 | 数据库默认 |
| --- | --- | --- | --- | --- |
| `start_week` | INTEGER | 否 | 1 | 1 |
| `end_week` | INTEGER | 否 | 20 | 20 |
| `teacher` | VARCHAR(100) | 是 | None | NULL |

`Base.metadata.create_all` 不会修改已有表，因此必须单独执行迁移。以下命令在 `backend` 目录运行：

```bash
.venv/bin/python scripts/migrate_schedule_weeks.py
.venv/bin/python scripts/migrate_schedule_weeks.py --check
```

第一条检查已有列，只为缺失字段执行 `ALTER TABLE ... ADD COLUMN`。第二条只读显示结构。迁移支持 MySQL 与 SQLite；不会重建表、删除记录、修改旧字段或外键。中途停止后可重跑，已存在字段直接跳过。

首次迁移使用的新增列定义为：

```sql
ALTER TABLE schedules ADD COLUMN start_week INTEGER NOT NULL DEFAULT 1;
ALTER TABLE schedules ADD COLUMN end_week INTEGER NOT NULL DEFAULT 20;
ALTER TABLE schedules ADD COLUMN teacher VARCHAR(100) NULL DEFAULT NULL;
```

实测第一次新增三个字段，第二次新增字段数为 0。迁移后、重造数据前，原 77 条课表的所有原字段、ID、`create_time` 和 `update_time` 均与迁移前一致，新字段为 `1 / 20 / NULL`，旧行仍可通过原有列表查询。

迁移后的实际 `schedules` 结构共 11 列：

| 字段 | MySQL 类型 | 可空 | 数据库默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 否 | 无 | 主键、自增 |
| `user_id` | INTEGER | 否 | 无 | 外键指向 `users.id` |
| `class_date` | DATE | 否 | 无 | 上课日期 |
| `period` | VARCHAR(50) | 是 | NULL | 四档节次 |
| `course_id` | INTEGER | 否 | 无 | 外键指向 `coruses.id`，保留原表拼写 |
| `location` | VARCHAR(100) | 是 | NULL | 上课地点 |
| `create_time` | DATETIME | 否 | 无 | ORM 在插入时填写 |
| `update_time` | DATETIME | 否 | 无 | ORM 在插入、更新时填写 |

主键及指向 `users` / `coruses` 的外键均保留。空值与默认值由数据库列定义保证，新旧业务调用均可省略新增字段。

最终只读 `SHOW CREATE TABLE schedules` 核对：存储引擎仍为 InnoDB，字符集排序规则仍为 `utf8mb4_unicode_ci`，表注释仍为“课程信息”。冒烟临时记录插入后已清理，自增序列正常增长，不要求恢复序列值。

## 周次与节假日工具

工具位于 `app/utils/semester.py`，日历数据集中在 `app/common/holiday_config.py`，没有写进排课逻辑。

| 函数 | 用途 | 示例 |
| --- | --- | --- |
| `week_date_range(N)` | 第 N 周转换成周一至周日的日期区间 | 第 1 周：09-07 至 09-13；第 20 周：2027-01-18 至 01-24 |
| `date_to_week(date)` | 学期内日期转换成周次 | 2026-10-10 → 第 5 周 |
| `is_class_day(date)` | 判断是否上课日 | 放假 False；调休日 True；其余周一至周五 True |
| `week_holiday_info(N)` | 返回当周是否含节假日、完整假期与当周交集、说明文案 | 第 4、5 周均提示 `10/1-10/7 国庆节放假` |

周次 0、21、非整数，学期外日期、无效日期格式或非周一学期起点，均抛明确的 `BusinessException(code=400)`。默认周次越界消息为“周次超出范围，请输入 1 至 20 的整数”；日期格式错误提示包含 `YYYY-MM-DD`。

假期和调休日期严格采用任务给定数据：

| 日期 | 配置 | 处理 |
| --- | --- | --- |
| 2026-09-25 至 09-27 | 中秋节 | 不排课 |
| 2026-10-01 至 10-07 | 国庆节 | 不排课，跨第 4、5 周 |
| 2027-01-01 至 01-03 | 元旦 | 不排课；2027 年正式安排尚未发布，按任务指定惯例推定，配置与说明均注明 |
| 2026-09-20，周日 | 调休上班日 | 排课，属于第 2 周 |
| 2026-10-10，周六 | 调休上班日 | 排课，属于第 5 周 |

放假判断优先于调休判断。调休日按实际星期定位：23 门模板课占用 20 个工作日格子、2 个周六格子、1 个周日格子。周六和周日有专属课程，只在指定调休日出现；不把其他星期的课程移动过来，确保同一门课的星期与节次始终固定。

## 种子命令与幂等实测

```bash
# 只读计算并打印 20 周安排，不新增、更新或删除数据库记录
.venv/bin/python tests/manual/seed_demo_schedules.py --preview

# 补齐缺失模板课，并同步 aaa / bbb 的整学期演示课表
.venv/bin/python tests/manual/seed_demo_schedules.py

# 仅使用现有模板课，不新增课程
.venv/bin/python tests/manual/seed_demo_schedules.py --no-courses

# 显式清理：先删演示课表，再删模板课程
.venv/bin/python tests/manual/seed_demo_schedules.py --clean

# 显式先清后建；课程和课表会重建，ID 与时间戳可以改变
.venv/bin/python tests/manual/seed_demo_schedules.py --reseed
```

普通重复运行按学生、日期、节次和课程复用同一记录；仅在字段发生变化时更新，未变化记录保留 ID 和时间戳。默认同步只覆盖启用的演示账号 `aaa` / `bbb` 及明确列出的 23 门模板课程，不清空整张表。非模板课程占用目标格子时返回 `409`：“演示排课与非模板课程冲突，请先调整冲突课表；未改动任何记录”。新增课程和同步课表在同一事务中，冲突时回滚。

`--clean` 先删课表、再检查课程是否仍被其他学生引用；存在引用返回 P5 风格的 `409`，整次清理回滚。`--reseed` 分别提交清理和生成两个事务，生成失败不会恢复已提交的清理；本次使用普通同步，没有执行 `--clean` 或 `--reseed`。幂等性以普通重复同步验证。`--preview` 不能与清理或重造参数同时使用，统计仅包含拟生成的模板课表。演示账号与模板课程范围内的手工课表也属于同步范围；非模板课程和其他学生的课表保留。
