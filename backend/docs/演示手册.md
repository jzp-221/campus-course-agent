## 一、5 分钟快速开始

### 一条命令启动

```bash
cd "/Users/jiazepin/Desktop/校园项目/campus-course-agent/scaffold"
./start.sh
```

脚本会：自检环境（Python/Node/依赖/Key/数据库/外部服务连通性）→ 启动 FastAPI(8000) → 启动 MCP(8001) → 启动前端(5173)。

**已在运行的服务会被复用，不会重复启动。**

### 要开三个"东西"，但只有一个要你操心

| 进程 | 端口 | 谁启动 |
| --- | --- | --- |
| MySQL | 3306 | 开机自启，一般不用管 |
| FastAPI | 8000 | `./start.sh` |
| **MCP** | **8001** | `./start.sh` ← **最容易忘记，忘了助手就查不了课表** |
| 前端 | 5173 | `./start.sh` |

### 打开

```
http://localhost:5173
```

### 停止

在跑 `start.sh` 的终端按 **Ctrl + C**。只关它启动的进程，你原有的服务不受影响。

## 二、演示前的 3 分钟检查

```bash
cd "/Users/jiazepin/Desktop/校园项目/campus-course-agent/scaffold"
./start.sh --check
```

要看到 **`失败 0 项`**。重点看这三行：

```
✓ MySQL 可连接：用户 3 · 课程 22 · 课表 314 · 知识库文档 4
✓ 对话模型：deepseek-chat，返回：正常
✓ Embedding：BAAI/bge-m3，向量维度 1024
```

第 2、3 行会**真实调用一次 API**——这是为了在演示前就发现"Key 欠费/过期"这种中途才爆炸的问题。

### 如果数据是空的

```bash
cd backend
.venv/bin/python tests/manual/seed_demo_schedules.py     # 22 门课 + 20 周课表
.venv/bin/python tests/manual/seed_demo_assignments.py   # 作业考试 + 计划任务
```

两个脚本都**幂等**，重复跑不会产生重复数据。

## 四、每个动作背后的技术点

如果评委/面试官追问，这些是能答出深度的点。**数字都是实测的**。

| 技术点 | 能说的事实 |
| --- | --- |
| **MCP 独立进程** | 工具跑在 8001 的独立进程里，FastAPI 通过 Streamable HTTP 调用。MCP 挂了助手会明确报"MCP 服务不可用"，不会假装回答 |
| **身份不由模型填写** | 工具的签名里**没有 `user_id` 参数**；JWT 从请求头一路传到工具，工具自己解析。模型就算被诱导传入 `user_id`，也会在工具执行**之前**被拦截（有测试断言此时工具未被调用） |
| **两阶段流式** | 先只让模型决定调工具（禁流式），再用 `tool_choice="none"` 硬约束后逐 token 推送。实测长回答 **673 个文字块跨 3.94 秒**逐步到达，工具事件全部在文字之前 |
| **检索失败 ≠ 没有命中** | 两种情况的返回结构不同：失败是 `{"error": "检索失败：...", "code": 502}`，没命中是 `{"items": [], "count": 0}`。所以助手不会用"资料里没有"掩盖"我根本没查到" |
| **阈值是标定的** | 口语化提问曾漏答（答案块排第 1 但距离 0.3814 > 阈值 0.35）。排查时**否掉了两个方案**：查询改写实测救回 0 个；混合检索无可分阈值。最终重新标定到 **0.40**（依据：最差答案块 0.3883 < 0.40 < 最近无关问题 0.4162） |
| **单轮最多保存一次** | 提示词会被绕过，所以有代码兜底。关键在顺序——`save_attempted` 在提交**之前**置位，覆盖"数据库已提交但响应丢失"时模型重试的场景 |
| **并发不丢更新** | 任务延期用单条原子 UPDATE（`defer_count = defer_count + 1`），实测 **8 个并发请求 → 计数精确为 8** |
| **Chroma 跨进程隔离** | FastAPI 和 MCP 两个进程共用一个 Chroma（SQLite），用**文件锁 + 短命子进程**隔离读写，避免并发写损坏 |

## 五、常见提问与回答

**Q：模型会不会瞎编？**
A：两层防护。① 提示词要求"检索不到就说没有"；② 代码层区分"检索失败"和"没有命中"，失败时不会返回空结果冒充。实测问"学校食堂几点开门"它会答"知识库中没有检索到相关内容"。

**Q：怎么保证学生看不到别人的数据？**
A：身份只从 JWT 解析，工具参数里没有 `user_id`。我实测过：学生 token 传 `?user_id=<别人>` 会被忽略，仍只返回自己的数据；操作他人记录返回 **404**（不是 403，不泄露记录是否存在）。

**Q：为什么不用现成的 Agent 框架一条龙？**
A：用了 LangChain 的 `create_agent`（底层 LangGraph），但**工具执行放在独立 MCP 进程**里。好处是工具能力与业务 API 解耦——比如调试时可以用 MCP Inspector 单独验证工具，不用起整个后端。

**Q：数据是自己造的还是有真实来源？**
A：课程、课表、作业是脚本生成的演示数据（22 门计算机专业课、20 周课表），但**节假日与调休日期是国务院办公厅 2026 年正式通知里的真实日期**。课程资料是我写的 4 份虚构课程文档，用于演示 RAG。

**Q：为什么检索有距离阈值？不能放宽吗？**
A：放宽会让无关问题被误召回，然后由模型判断"这段没回答问题"——**误召回比漏答更危险**，因为它可能诱导模型基于无关内容作答。所以阈值是标定出来的，注释里写明了依据和"换 embedding 模型必须重新标定"。

## 六、出问题时的应急处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 助手说 **"MCP 服务不可用"** | 8001 没启动 | `./start.sh`（会复用已在运行的服务，只补 MCP） |
| 课程详情页资料区显示**红色错误** | 同上，资料检索依赖 MCP | 同上 |
| 冒烟脚本报 **"8001 已被占用"** | 手工开的 MCP 占着端口（脚本按设计不杀别人的进程） | `./start.sh --restart-mcp` |
| 自检报 **"数据库连接失败"** | MySQL 没启动 | `mysql-status` 查看；`mysql-start` 启动 |
| 自检报 **对话模型 / Embedding 失败** | Key 过期或欠费 | 检查 `backend/.env` 里的 `LLM_API_KEY` / `EMBEDDING_API_KEY` |
| 页面打开是空白 | 前端没起来 | 确认 5173 在跑；或 `cd frontend && npm run dev` |
| 助手回答很慢 | 每次提问会调 1~2 次模型 + 可能一次 embedding | 正常现象，通常 3~6 秒 |

### 完全重置（数据丢失时）

```bash
cd backend
.venv/bin/python scripts/migrate_schedule_weeks.py
.venv/bin/python scripts/migrate_assignments_and_tasks.py
.venv/bin/python tests/manual/seed_demo_schedules.py
.venv/bin/python tests/manual/seed_demo_assignments.py
```

课程资料需要重新用 admin 登录 →「知识库文档」上传 `backend/docs/demo/课程资料/` 下的 4 份文件（支持一次批量上传）。
