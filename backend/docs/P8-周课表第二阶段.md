## 单周接口

```http
GET /api/schedules/week?week=5
Authorization: Bearer <当前登录学生的 JWT>
```

返回仍使用 `{"code":200,"message":"请求成功","data":...}` 包装。`data` 字段如下：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `week` | 整数 | 实际查询的周次，1 至 20 |
| `user_id` / `username` / `name` | 整数 / 字符串 / 字符串 | 被查询账号的身份；用于显示正在查看谁的课表 |
| `start_date` / `end_date` | 日期字符串 | 当周周一至周日，`YYYY-MM-DD` |
| `is_current_week` | 布尔值 | 当周是否包含今天 |
| `current_week` | 整数或 null | 今天对应的学期周次；学期外为 null |
| `today` | 日期字符串 | 用于今天高亮的日期 |
| `total_weeks` | 整数 | 学期总周数，20 |
| `semester_start_date` / `semester_end_date` | 日期字符串 | 学期起止日期 |
| `periods` | 字符串数组 | `1-2节 / 3-4节 / 5-6节 / 7-8节`，顺序即网格行顺序 |
| `days` | 七个日期对象 | 按周一至周日排列，空日同样返回 |
| `has_holidays` | 布尔值 | 当周是否与配置假期重叠 |
| `holiday_notice` | 字符串 | 复用 `week_holiday_info()` 的完整假期说明 |

每个 `days` 对象包含 `date`、`weekday`（1 至 7）、`is_class_day`、`is_today`、`is_holiday`、`holiday_name` 与 `courses`。`courses` 始终为数组，空档由前端按照 `periods` 补足格子；每条课程包含以下字段：

```json
{
  "id": 123,
  "user_id": 2,
  "period": "3-4节",
  "course_id": 42,
  "course_name": "算法设计与分析",
  "teacher": "郭景行",
  "location": "信息楼机房402",
  "start_week": 1,
  "end_week": 16
}
```

上面 ID 为结构示例，不代表实际数据库 ID。课程名称来自课程表联查，网格不拼装名称。记录必须同时满足：已鉴权确定的查询用户 ID、`class_date` 落在该周日期区间、`start_week <= week <= end_week`、当日 `is_class_day()` 为真。

学生即使追加 `user_id=<另一位学生>`，也只能查 Authorization 对应账号的课表。管理员可用 `user_id` 查看指定学生；省略时只查管理员自己，不默认合并所有人的课表。指定账号不存在时返回业务 404。响应的 `user_id` / `username` / `name` 始终属于被查询账号。没有 Token 或 Token 无效时，在查询前拒绝并返回 HTTP 401 和业务码 401。`week=0`、`week=21`、`week=abc`、`week=1.5` 返回带明确消息的业务码 400，不走数据库异常或 500。

省略 `week` 时查询上海时区的当前学期周；今天在学期前则显示第 1 周，在学期后则显示第 20 周，同时 `current_week=null`、`is_current_week=false`。四档以外的节次返回业务 400，同格重复课程返回业务 409 并提示调整课表，不通过叠放或静默丢弃记录隐藏数据问题。

现有 `GET /api/schedules` 的分页结构和行为保留，没有用周接口替代列表接口。本阶段不新增一次查询多周的批量接口：单周载荷较小，前端缓存已经访问过的周次即可减少来回切换的请求。

## 前端访问与对接

在项目的 `frontend` 目录运行既有 Vite 命令：

```bash
cd ../frontend
npm run dev
```

登录学生账号后，通过侧边菜单“周课表”访问 `/manager/schedule-week`。原“我的课表”列表入口保留，`Schedule.vue` 与 `ScheduleManage.vue` 不做替换。

管理员也可访问该页面，通过学生选择入口查看指定学生。学生页面不显示该控件。身份提示使用服务端返回的账号标识；切换学生时不会复用另一位学生的周缓存。

视图为七列日期、四行节次，空档和普通周末保留完整格线。上方提供上一周、下一周与回到本周，第 1 周和第 20 周分别禁用越界方向。左右方向键提供同样的翻周操作；焦点在输入框、可编辑区域或对话框内，输入法正在组合文字，或按下修饰键时，不触发翻周。表头和节次列固定，窄屏通过横向滚动保持卡片宽度；只有周课表路由在宽度不超过 720px 时使用 64px 图标侧栏，菜单保留标题和无障碍名称，其他页面布局保留。左侧显示“1-2节”等节次与“共 2 节”；项目没有提供作息时间配置，本阶段不编造具体钟点。

课程卡片使用稳定的 `course_id` 哈希选择 Element Plus 调色板；同一门课翻周或刷新时颜色相同。卡片显示课程名、教师、节次、地点及周次范围，超出固定高度的文字用省略号和完整信息提示处理。本周、今天、假期和调休日有对应标记。

页面使用项目既有鉴权约定发送 GET 请求。首次省略 `week`，以服务端返回的当前周和学期配置初始化。已经成功获取的周次存入当前页面缓存；来回切换复用缓存，同周并发请求合并，快速翻周时旧响应不会覆盖新周。加载、空课表与请求失败都有各自界面；“重新加载”强制刷新该周，切换周次保留网格容器和滚动位置。缓存仅属于当前页面实例，不跨账号持久化。

## 真实只读冒烟

先启动 MySQL 和已配置的 FastAPI。若 FastAPI 未运行：

```bash
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

周接口不经 MCP，也不需要 LLM/embedding Key；验证脚本不会启动 8000 或 8001，不会读取 `.env`，不会上传、排课、删除或修改任何记录。它通过真实 `POST /api/auth/login` 获取 `aaa` / `bbb` / `admin` 的 JWT，Token 不打印到终端。

```bash
.venv/bin/python tests/manual/week_schedule_smoke.py
```

演示学生默认密码为 `123`。如本机调整了密码，可以在运行环境中提供 `E2E_AAA_PASSWORD`、`E2E_BBB_PASSWORD`；不要把密码或 JWT 写入脚本和文档。

管理员默认账号/密码为 `admin` / `admin`，可用 `E2E_ADMIN_USERNAME` / `E2E_ADMIN_PASSWORD` 覆盖。

以下为 P8/P9 时的历史验收项目与输出。P10 的当前脚本保留接口、日期、假期、管理员和防越权断言，并按各自列表动态统计，新增每周有课格差异至少 80% 与双学生并排网格；不再要求两人各 254 条。任意失败退出码非 0。

1. 两名学生逐周读取 1 至 20 周，每周有课，累计各 254 条，与原列表接口的本人记录集合完全一致。
